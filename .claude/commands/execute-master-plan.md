# تنفيذ الخطة الرئيسية — EMC Frontend (v2.1 — وضع الإنهاء المُقتصِد)

أنت منفّذ الخطة الرئيسية لواجهة EMC في `C:\EMC\WEP`. استخدم أداة Bash (لا PowerShell). نفّذ دون الرجوع للمستخدم إلا عند بوابات المؤسس أو فشل غير قابل للإصلاح.

> **الموضع:** المشروع في مرحلته الأخيرة (M7 ثم M8). **المطلوب إنهاء وتوثيق وتسليم — لا إعادة بناء.**

## ⚡ اقتصاد التنفيذ (إلزامي — خطة §4.1)
- **العمل المباشر هو الأصل.** لا تُطلق وكلاء إلا إذا تحقّقت **كل** الشروط: عمل متوازٍ فعلاً · ملفات منفصلة تماماً · **≥4 ملفات لكل وكيل**. المهام المفردة/التوثيقية/الإعدادية → نفّذها بنفسك.
- **سقف 3 وكلاء لكل مرحلة** (لا لكل دفعة).
- **البوابة الكاملة عند إغلاق المرحلة فقط.** داخل المرحلة: `eslint --quiet` + الاختبارات **المستهدَفة** للملفات المتأثّرة فقط.
- **قراءة موجَّهة:** Grep/أسطر محدّدة بدل ملفات كاملة؛ لا تُعِد قراءة ما في سياقك.
- **لا إعادة توليد `coverage/`/`dist/`** إلا لتقرير الإغلاق.
- **لا إعادة هيكلة واسعة جديدة.** أي فكرة تحسين خارج دفتر المرحلة → سطر في `docs/02-planning/improvement-backlog.md`، لا تنفيذ.

## بروتوكول البدء (إلزامي، بالترتيب، قبل أي شيء)
1. اقرأ: `docs/02-planning/master-plan/STATE.md` (الموضع والدفاتر) ثم `docs/02-planning/MASTER_PLAN.md` (المراحل + نموذج §4 + الحوكمة §7) ثم `docs/04-references/brand/EMC_Brand_Master.v3.md` (قوانين الهوية — ملزمة).
2. `git status` — إن كانت الشجرة غير نظيفة: طابِقها مع دفتر STATE (أكمل الدفعة الناقصة: تحقّق ثم commit، أو تراجَع إلى `backup/pre-M<n>` حسب ROLLBACK.md) **قبل** أي fetch.
3. `git fetch origin` ثم افحص الانحراف: إن لم يعد SHA المسجَّل في STATE (`آخر origin/dev مدموج`) سلفاً لـ`origin/dev` الجديد (`git merge-base --is-ancestor`) فهذا force-push/rebase → **توقّف صلب: اعرض الوضع كبوابة مؤسس**. تقدّم طبيعي؟ ادمجه بسياسة «وظيفة الفريق تَغلِب» وحدّث SHA في STATE قبل المتابعة.

## التنفيذ
4. نفّذ **الدفعة التالية غير المكتملة** من دفتر المرحلة الجارية في STATE، بنموذج الخطة §4:
   - فرع أمان `backup/pre-M<n>` عند بدء مرحلة جديدة.
   - استكشاف قراءة-فقط **موجَّه** عند الحاجة → نفّذ مباشرةً (أو بوكلاء **فقط** إن استوفت شروط §4.1 أعلاه؛ حينها: بيان ملكية ملفات مكتوب بصفر تداخل، والمفردات Singletons — index.css، tailwind.config.js، package.json+lock، index.html، جدول مسارات App.tsx، STATE، الإعدادات — للمنسّق وحده؛ الوكلاء لا يشغّلون npm/git أبداً) → **تحقّق الدفعة:** `npx eslint . --quiet` (0) + الاختبارات المستهدَفة + `grep -rl "^<<<<<<<" src/` فارغ → **commit الدفعة** `M<n>.<batch>: <وصف>` و`Co-Authored-By: Claude`.
   - **عند إغلاق المرحلة فقط:** البوابة الكاملة `npm run build` + `npm test` + `npx playwright test` + `typecheck:strict` + `check:secrets` + `npm audit`.
5. بعد كل دفعة: حدّث دفتر STATE (المربعات + أي SHA) · وبعد كل مرحلة: سطر CHANGELOG + `docs/03-changes/M<n>-report.md` (باللقطات إن وُجدت) ثم تابع المرحلة التالية.

## التوقّف
توقّف فقط عند: **بوابة مؤسس** تعترض المسار (اعرضها سؤالاً واضحاً بخيارات، وسجّل قراره نصاً في STATE عند وروده) · فشل تحقّق غير قابل للإصلاح آلياً (اعرض التشخيص) · انحراف force-push (البند 3).

## ممنوعات قطعية
- الدفع للريموت (push) بأي شكل بلا أمر صريح من المستخدم.
- كسر وظيفة للفريق · حذف أي شيء ظاهر/مُصدَّر دون «إخفاء بعلم → تجربة مرحلة → بوابة مؤسس» (خطة §2.3).
- مخالفة هوية V3: مزج بحر↔نار في تدرّج · سماوي/برتقالي نصاً على فاتح · تعديل الشعار · خطوط غير ثمانية بعد بوابة الترخيص.
- **commit أي ملف خط من `public/fonts/thmanyah/` أو subsetting قبل بوابة الترخيص** (المجلد في .gitignore — لا تُزل السطر).
- نشر/إظهار أرقام أو روابط أو أسعار غير مؤكَّدة من المؤسس.
- **إضعاف البوابات لتمريرها:** لا تعديل eslint/tsconfig/vitest/playwright/ci.yml ولا `test.skip` ضمن جعل بوابة تنجح — أي تعديل إعدادات كهذا commit مستقل ببوابة مؤسس ومبرّر في STATE.
- git المدمّر: `reset --hard` (خارج ما توثّقه ROLLBACK)، `push --force`، `branch -D backup/*`، `filter-branch`، حذف فروع الأمان.
- تعديل نصوص بوابات المؤسس في STATE (تسجيل قراراته فقط).
- معرّفات جلسات/ورش في STATE — مراجع ملفات/فروع/SHA فقط.
- تثبيت حزمة npm جديدة دون تسجيلها في STATE ومرورها `npm audit` قبل commit إدخالها.
