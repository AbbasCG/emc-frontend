## 2) 🔴 خلل إنتاجي اكتشفته اختبارات M7.A — ازدواج تسجيل مخالفات الاختبار

`src/hooks/useExamLockdown.ts` كان يبلّغ عن المخالفة **من داخل** مُحدِّث الحالة:

```js
setFullscreenExitCount((prev) => {
  const next = prev + 1
  report('fullscreen_exit', { exit_count: next })   // ← أثر جانبي داخل مُحدِّث
  toast.warning(...)
  return next
})
```

React **يعيد استدعاء المُحدِّثات** — والتطبيق يركّب داخل `StrictMode` (`src/main.tsx:17`). النتيجة الفعلية: **كل خروج من وضع ملء الشاشة كان يُسجَّل على الخادم مرّتين، ويُنبَّه الطالب مرّتين، ويُحتسب مرّتين ضدّه** — أي أن طالباً خرج مرّة واحدة يظهر في سجلّ المخالفات بمخالفتين.

**الإصلاح:** الحصيلة تُشتقّ من `ref`، والآثار الجانبية تبقى في معالِج الحدث (يعمل مرّة واحدة لكل حدث)، والمُحدِّث صار نقيّاً. **اختبار انحدار** يؤكّد تسجيلاً واحداً لكل خروج تحت غلاف `StrictMode` صراحةً.

## 3) 🔴 خلل في أداة القياس — التغطية كانت مُضخَّمة

`vitest run --coverage` **يُضخّم النسب على هذا المستودع**. أي وحدة تُستورَد كسولاً عبر السلسلة أثناء الحزام لكنها **لا تُنفَّذ** تعود من مزوّد v8 بـ«0 مغطّى / **0 إجمالي**» بدل «غير مغطّاة بالكامل» — فتسقط من المقام كليّاً وترتفع كل نسبة فوقها.

- **الأثر المقيس: 284 ملفاً و16,642 سطراً تنفيذياً تختفي من المقام.**
- التطبيق كاملاً كان يُعلَن **41.96%** بينما الحقيقة **22.35%**.
- `coverage.all: true` **لا يمنعه**: الملف نفسه يُقاس صحيحاً في تشغيل لا يلمسه إطلاقاً (تحقُّق مباشر: `MembersPage.tsx` يعطي 0/0 في الحزام الكامل، ويعطي أسطره الحقيقية 35–1346 في تشغيل معزول).
- هذا يفسّر بأثر رجعي ملاحظة M7.B في STATE عن «`coverage/` بنطاق منكمش غير موثوق» التي بقيت بلا سبب معروف.

**الحل:** `scripts/coverage-truth.mjs` + `npm run coverage:truth` — قياس بممرّتين: الأعداد **المغطّاة** من الحزام الحقيقي، والإجماليات **الصحيحة** من مسح مقام بملف اختبار واحد. كل أرقام §1 مقيسة بهذه الطريقة.

### C — hex الخام مقابل الـtokens (`82ce241`)
**الجرد:** remap الألوان في M0 أعاد كتابة الألوان **في مكانها كـhex خام**، فبقيت **5,494 نسخة في 384 ملفاً** — 77% منها القيم الثلاث الأساسية لهوية V3، ولكلٍّ منها token دقيق أصلاً (`navy` · `customBlue` · `customOrange`). تحويلها كلّها إعادة هيكلة واسعة تمنعها خطة v2.1، فالبوابة **تُثبّت الخط** بنصفين:

1. **ESLint** — `no-restricted-syntax` بمستوى `error` على الـhex في السلاسل النصية وقوالبها، مُطبَّقة على **كل ملف نظيف أصلاً (634 ملفاً) وكل ملف جديد**. القائمة القديمة مستثناة صراحةً، و**لا يجوز أن تنمو**.
2. **`npm run check:brand`** (+ خطوة CI) — ملف خارج الأساس يجب أن يحوي **صفر** hex؛ وملف داخل الأساس **لا يتجاوز عدده المسجَّل أبداً** (القديم يتقلّص فقط).

**تحقُّق أن البوابة تعضّ فعلاً** (ثلاث زرعات، كلها أُزيلت بعدها):

| الزرع | النتيجة |
|---|---|
| ملف جديد فيه `text-[#123456]` | ESLint أطلق `no-restricted-syntax` ✅ |
| الملف نفسه غير مُدرَج في الأساس | `NEW FILE ... — 1 raw hex value` ✅ |
| +2 hex في `MembersPage.tsx` | `GREW ... 105 raw hex values, baseline allows 103` ✅ |

### B — `strict: true` (`0d612e1`)
قفزة واحدة على كل `src` أعطت **صفر أخطاء** (أثر تأنيع M0/M4.b). تحقُّق أن الفحص ليس فارغاً: زُرع `string = null` → `TS2322` ظهر → أُزيل.
