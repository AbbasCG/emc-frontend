# 📚 مركز توثيق مشروع EMC Frontend

> **هذا الملف هو المرجع الرئيسي (Single Source of Truth) لكل التقارير والخطط والتعديلات في المشروع.**
> ابدأ من هنا دائماً. كل وثيقة مفهرسة أدناه مع رابط مباشر.

- **المشروع:** `emc-frontend` — واجهة React الأمامية لمنصّة EMC التعليمية (عربية أولاً · RTL)
- **المستودع:** https://github.com/AbbasCG/emc-frontend
- **الفرع المعتمَد:** `dev` ← **هو الأساسي** (فرع `main` مجرّد هيكل Vite فارغ)
- **المسار المحلي:** `C:\EMC\WEP`
- **الحجم الفعلي:** 752 ملفاً · ‎~107,700 سطر · ~350 مساراً · ~30 نطاق مكوّنات
- **التقنية:** React 19 · TypeScript 6 · Vite 8 · React Router 7 · Tailwind 3 · framer-motion · axios · Sentry · recharts · vitest
- **الخادم:** واجهة Laravel REST منفصلة (`/api`)
- **تاريخ آخر فحص شامل:** 2026-06-21 (فحص عميق متعدد الوكلاء — 18 وكيلاً)

## ⚡ الحالة في سطر واحد

> **🟠 تطبيق ناضج وغنيّ بالميزات (LMS كامل · RBAC · تقويم · دفع) — لكنه يحتاج مرحلة استقرار قبل الإطلاق:** الـ lint يفشل (+3 أخطاء حقيقية)، 5 ثغرات تبعيات، لا CI، تغطية اختبار ~0.5%، ولا طبقة i18n. البناء أخضر وTypeScript نظيف.

## 🔄 كيف نستخدم هذا التوثيق؟

1. **قبل أي عمل:** اقرأ [الملخّص التنفيذي](01-assessment/00-executive-summary.md) ثم التقرير ذا الصلة.
2. **عند التخطيط لميزة/إصلاح:** راجِع [قائمة التحسينات](02-planning/improvement-backlog.md) و[خارطة الطريق](02-planning/roadmap.md).
3. **عند قرار تقني مهم:** سجّل ADR في [`02-planning/architecture-decisions/`](02-planning/architecture-decisions/).
4. **بعد أي تعديل:** أضِف سطراً في [CHANGELOG](03-changes/CHANGELOG.md).
5. **أثناء الكتابة:** التزم بـ[دليل الاصطلاحات](04-references/conventions.md).
