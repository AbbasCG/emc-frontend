## 1. الخلاصة التنفيذية

التطبيق ناضج وكبير بحق: 752 ملفًا مصدريًا في `src/` (570 ملف `.tsx` + 181 ملف `.ts`) بحوالي 107,716 سطر، موزَّعة على ~30 نطاق مكوّنات و~18 نطاق صفحات. البنية منظَّمة (`api/`, `components/`, `contexts/`, `hooks/`, `layouts/`, `pages/`, `services/`, `types/`, `utils/`)، والطبقات الأساسية (التوجيه، التحكم بالأدوار، طبقة الـ API المُحصَّنة) عالية الجودة.

الصورة العامة لجودة الكود **مختلطة لكنها قابلة للإصلاح**:

- 🟢 **صحّة الأنواع ممتازة**: أمر البناء `tsc -b && vite build` ينجح في ~2.24 ثانية، و**TypeScript يُترجَم نظيفًا تمامًا** رغم دَيْن الـ lint — مؤشّر صحّة قوي على مستوى الأنواع. كذلك `noUnusedLocals` / `noUnusedParameters` / `noFallthroughCasesInSwitch` مُفعَّلة على مستوى المُترجِم.
- 🔴 **الـ lint يفشل (خروج 1)** بعشرات النتائج، من بينها **3 أخطاء صحّة حقيقية** (انظر §3‑أ) تستحق الإصلاح الفوري.
- 🟠 **لا يوجد CI** على الإطلاق: الاختبارات والـ lint والـ build تُشغَّل يدويًا فقط على جهاز Windows لدى المطوّر — لا شيء يمنع دمج تغيير يكسر البناء أو يفشل الـ lint.
- 🟡 **دَيْن اتّساق وتكرار**: طبقة `api/` تحتوي مولّدات متعدّدة لنفس منطق فكّ تغليف الاستجابة، وملفات ضخمة (God files)، ومكتبتا إشعارات (toast) متوازيتان، إضافة إلى مخلّفات (حزمة `i`، ملف `dir` فارغ متتبَّع، وثائق قديمة مُضلِّلة).

**التوجيه الأساسي للمعالجة**: أصلِح الأخطاء الثلاثة الحقيقية أولًا → ثبِّت قاعدة الـ lint خضراء → أَلزِم ذلك عبر CI → نظِّف التكرار والمخلّفات.

## 3. دَيْن الـ Lint — التصنيف

`npm run lint` يفشل (خروج 1). نُصنِّف النتائج إلى ثلاث فئات بحسب الخطورة الفعلية.

### 3‑أ) أخطاء صحّة حقيقية 🔴 (تُصلَح فورًا)

هذه ليست مجرّد نظافة — لكلٍّ منها أثر سلوكي مؤكَّد.

#### (1) `SessionCard` يستدعي `Date.now()` أثناء الرسم — `react-hooks/purity`
**الملف**: `src/components/lms/SessionCard.tsx:47`

```tsx
const joinState = getSessionJoinState(session, Date.now(), joinMeetingLabel ?? 'انضم للجلسة')
```

قراءة `Date.now()` داخل جسم الرسم تجعل المخرَج معتمدًا على الزمن (غير نقي)، مع أثرين حقيقيين:
1. قد يتعارض الرسم تحت `StrictMode`/الوضع المتزامن في React 19 (رسم مزدوج).
2. نافذة الانضمام (بوّابة 10 دقائق قبل البدء) تُقيَّم **مرّة واحدة فقط** عند الرسم؛ لا يوجد أيّ `setInterval`/مؤقّت في `SessionCard`. عمليًا: الطالب الجالس على صفحة الجلسات **لن يرى زرّ «انضم للجلسة» يظهر تلقائيًا** عند فتح النافذة — يجب إعادة التحميل أو إثارة إعادة رسم غير مرتبطة.

**الإصلاح المقترح** — رفع الساعة إلى حالة:
```tsx
const [now, setNow] = useState(() => Date.now())
useEffect(() => {
  const id = setInterval(() => setNow(Date.now()), 30_000)
  return () => clearInterval(id)
}, [])
const joinState = getSessionJoinState(session, now, joinMeetingLabel ?? 'انضم للجلسة')
```
يُصلح هذا خطأ الـ purity ويجعل زرّ الانضمام يظهر/يختفي في الزمن الحقيقي.

#### (2) إنشاء مكوّنات أثناء الرسم في قسمَي الفريق — `react-hooks/static-components`
**الملفات**: `src/components/team/DepartmentSection.tsx:22,39` و`src/components/team/ExecutiveSection.tsx:16,23`

كلاهما يُنشئ `const Icon = resolveDepartmentIcon(...)` أثناء الرسم ثم يستخدمه كـ `<Icon .../>`، ما يُطلق التحذير «Cannot create components during render». لأن `resolveDepartmentIcon` يُعيد مرجع أيقونة `lucide` مستقرًّا، فالأثر العملي على إعادة ضبط الحالة منخفض اليوم، لكنه **خطأ lint يكسر CI** ونمط هشّ (أيّ أيقونة ذات حالة مستقبلًا ستُعاد تركيبها صامتةً).

**الإصلاح المقترح**: عرّف مكوّن غلاف على مستوى الوحدة يأخذ مفتاح الأيقونة بروبًا ويُحلِّله داخليًا، مثل `<DeptIcon iconKey={...} />`.

#### (3) شرط `&&` ثابت الصدق في `HomeCourseCard` — `no-constant-binary-expression`
**الملف**: `src/components/home/HomeCourseCard.tsx:119`

```tsx
{(startDate || hours != null || true) && (
  <div className="mt-3.5 ... border-t ...">
```

`|| true` يجعل الشرط ثابت الصدق دائمًا، فكتلة البيانات الوصفية (الفاصل المحدود بحدّ علوي وصفّ الموقع) **تُرسَم دائمًا** حتى دون تاريخ بدء ودون ساعات. الحارس المقصود غالبًا كان `(startDate || hours != null)`.

**الإصلاح المقترح**: احذف `|| true`؛ وإن كان صفّ الموقع يجب أن يظهر دائمًا فارسمه خارج الكتلة المحروسة.

| # | القاعدة | الملف:السطر | الأثر السلوكي |
|---|---------|------------|----------------|
| 1 | `react-hooks/purity` | `SessionCard.tsx:47` | زرّ الانضمام لا يظهر في الزمن الحقيقي + لاطهارة الرسم |
| 2 | `react-hooks/static-components` | `DepartmentSection.tsx:22,39`، `ExecutiveSection.tsx:16,23` | نمط هشّ + كسر CI |
| 3 | `no-constant-binary-expression` | `HomeCourseCard.tsx:119` | الكتلة الوصفية تُرسَم دائمًا (منطق ميّت) |

### 3‑ب) تحذيرات ذات خطر صحّة 🟡 (تُراجَع بعناية)

عشرات تحذيرات `react-hooks/set-state-in-effect` و`react-hooks/exhaustive-deps` منتشرة عبر **~30 ملفًا** (من بينها `DashboardLayout`, `AuthContext`, `Navbar`, والعديد من النوافذ والمنتقيات). أغلبها أنماط حميدة من نوع «إعادة ضبط الحالة عند تغيّر الـ prop/المسار»، لكنها مُعلَّمة وتُضيف ضجيجًا يُخفي الأخطاء الحقيقية. ملاحظة: إعداد ESLint (`eslint.config.js`) يُخفِّض عمدًا `react-hooks/set-state-in-effect` إلى `warn` مع تعليق مُبرِّر — أي أن الفريق على دراية بها.

**التوصية**: لا تُعالَج جملةً واحدة؛ تُراجَع ملفًا ملفًا بعد إخضرار الأخطاء الحقيقية، مع توثيق الأنماط الحميدة بـ `eslint-disable-next-line` مُعلَّل عند الحاجة لتقليل الضجيج.
