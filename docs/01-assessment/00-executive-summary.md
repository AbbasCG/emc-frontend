# الملخّص التنفيذي — تقييم واجهة EMC الأمامية

ملخّص قيادي مكثّف لنتائج التقييم العميق لمستودع `emc-frontend` (الفرع `dev`)، يجمع أبرز ما ورد في التقارير السبعة في صفحة واحدة قابلة للتصفّح السريع.

آخر تحديث: 2026-06-21 · الفرع: dev

---

## 1. ما هو التطبيق وما درجة نضجه الحقيقي

`emc-frontend` هو **واجهة React أمامية لمنصّة تعليمية عالمية (EMC)** موجّهة إلى الطلاب والمهاجرين والباحثين عن تغيير مساراتهم المهنية، عربية أولاً (Arabic-first) و RTL بالكامل، تتحدّث إلى **واجهة Laravel REST منفصلة**. هو **تطبيق ناضج وكبير الحجم فعلاً — وليس نموذجاً أولياً (scaffold)**: 752 ملف مصدري (570 `.tsx` + 181 `.ts`)، ‎~107,716 سطراً، ~30 نطاق مكوّنات و~18 نطاق صفحات، وجدول توجيه مركزي بـ ‎~350 مساراً مع تقسيم كود عدواني (182 استدعاء `lazy()`).

النواة الوظيفية ناضجة بشكل لافت — نظام LMS متكامل (واجبات + تسليمات + مراجعة، جلسات بمنطق نافذة انضمام، حضور بقفل خادمي، تقييم شفهي بمعايير rubric، اختبارات تحديد مستوى)، تقويم بأربعة عروض + تصدير ICS، تدفّق تسجيل ودفع متعدد المزوّدات، ومحرّك صلاحيات (RBAC) من 20 دوراً مُختبَر بوحدة — بينما الدَّيْن التقني حقيقي أيضاً: الـ lint يفشل، لا توجد طبقة i18n، لا CI، الاختبارات رقيقة (~0.5%)، و5 ثغرات تبعيات. **TypeScript يُترجَم نظيفاً والبناء أخضر في ‎~2.24s** — مؤشّر صحّة أنواع قوي رغم دَيْن الـ lint.

## 2. الحالة العامة (الحُكم)

> **🟠 صالح للإنتاج مشروطاً — أساس قوي مثقَل بدَيْن قابل للمعالجة.**

التطبيق غنيّ بالميزات ومنظَّم معمارياً (توجيه، RBAC، طبقة API مُحصَّنة، تقسيم كود)، لكنه **ليس جاهزاً للإطلاق دون مرحلة استقرار**: يجب أولاً إصلاح الأخطاء الثلاثة الحقيقية، وتشغيل `npm audit fix` (وضمنه رفع `dompurify`)، وإخضرار الـ lint، وإضافة بوّابة CI. الأمن يحتاج مراجعة (token في localStorage، تفويض عميل-فقط)، و i18n بند خارطة طريق لا قدرة حالية. النضج الأعلى في شريحة LMS؛ الدَّيْن الأبرز في البنية التحتية (CI/اختبارات) و i18n والأمن.

| البُعد | التقدير |
|---|---|
| المعمارية والتوجيه و RBAC | 🟢 قوي |
| طبقة الـ API والأنواع | 🟢 قوي (ثغرات تشغيلية: timeout/abort) |
| نضج الميزات (LMS/الدفع/التقويم) | 🟢 ناضج |
| جودة الكود والـ lint | 🟠 يفشل الـ lint + 3 أخطاء حقيقية |

| الوصول و SEO و RTL | 🟠 أساس جيد مُقوَّض |

## 4. أكبر المخاطر (تجميع مركّز)

- **الأخطاء الثلاثة الحقيقية** (lint): زرّ «انضم للجلسة» لا يظهر بالزمن الحقيقي، كتلة بيانات تُرسَم دائماً، ومكوّنات تُنشأ أثناء الرسم — أثر سلوكي مؤكَّد + تكسر CI.
- **5 ثغرات تبعيات (3 HIGH + dompurify)**: dompurify هو خط دفاع XSS الفعلي وبه تجاوزات معروفة؛ يتقاطع مع تخزين الـ token في localStorage فيرفع خطر سرقة الجلسة.
- **الـ lint غير أخضر + لا CI**: لا حاجز يمنع دمج كسر؛ أعلى إصلاح رافعةً.
- **وثائق قديمة مُضلِّلة**: README و CODEBASE_ANALYSIS يصفان تطبيقاً أصغر («لا اختبارات/لا تقسيم كود/API مثبّت» — كلها لم تعد صحيحة)، و AGENTS.md قصاصة غير ذات صلة.
- **مكتبتا toast**: ازدواج تبعية ووزن ووهْم خيار.
- **اختبارات رقيقة**: ثقة زائفة من مجموعة تغطّي 4 ملفات utils فقط، صفر تغطية للتوصيل الأمني الحرج.
- **لا طبقة i18n**: عربي مفرد بنيوياً؛ أي دعم EN/NL يتطلّب لمس كل ملف تقريباً.

## 5. الإجراءات الفورية (TOP)

ترتيب موصى به للأسبوع الأول من العمل:

1. 🔴 **`npm audit fix`** ثم `npm run build && npm test` — يُصلح الـ5 ثغرات ويرفع `dompurify` إلى ≥ 3.4.11.
2. 🔴 **إصلاح الأخطاء الثلاثة الحقيقية** — `SessionCard.tsx:47`، `Department/ExecutiveSection`، `HomeCourseCard.tsx:119`.
3. 🔴 **إخضرار الـ lint** بعد الأخطاء الثلاثة (`eslint --fix` للنظافة + فصل تصديرات `react-refresh`).
4. 🔴 **إضافة بوّابة CI (GitHub Actions)** — `npm ci && npm run lint && tsc -b && npm test && npm run build && npm audit --audit-level=high`.
5. 🔴 **استبدال `public/favicon.svg`** (493KB raster) بـ favicon صغير حقيقي (بضعة KB).
6. 🟠 **تنظيف المخلّفات**: `npm uninstall i sonner`، حذف `dir` و`C:tempteam_data.txt` و`AGENTS.md`، تصحيح `.env.example`.
7. 🟠 **مراجعة الأمن**: توثيق أن التفويض على العميل فقط + تأكيد مطابقة Laravel خادمياً؛ والتخطيط لنقل الـ token إلى كوكيز `httpOnly`.
8. 🟠 **إصلاح الوثائق القديمة**: تحديث/حذف README و CODEBASE_ANALYSIS.
