## 2) المبادئ الحاكمة

1. **وظيفة الفريق أولاً** — منطقهم/بياناتهم/مساراتهم تَغلِب؛ طبقتنا تُعاد فوقها.
2. **الحذف قبل الإضافة** — والتبسيط لا يلمس شيئاً قبل وجود حزام أمان E2E (M1.5).
3. **إخفاء قبل حذف — إلزامي:** أي عنصر ظاهر للمستخدم أو export عام: يُخفى بعلم في مرحلة N، يبقى مخفياً مرحلة N+1، ولا يُحذف إلا ببوابة مؤسس. جرد "الكود الميت" يجب أن يفحص `lazy()` والمسارات النصية ويقارن مع رأس `origin/dev`.
4. **أخضر دائماً + ممنوع إضعاف البوابات:** لا commit إلا بعد lint(0)+build+tests. **يُمنع منعاً باتاً** — لتمرير بوابة — تعديل eslint/tsconfig/vitest/playwright/ci.yml أو إضافة `test.skip`؛ أي تعديل إعدادات كهذا = commit مستقل ببوابة مؤسس ومبرّر في STATE.
5. **هوية V3 قانون** (لا مزج بحر↔نار، سماوي/برتقالي ليسا نصاً على فاتح، ثمانية حصرياً بعد بوابة الترخيص، الشعار مقفول، حدّ توقيعين/مشهد).
6. **قرارات المنتج للمؤسس** — بوابات صريحة في STATE.
7. **التوثيق إلزامي** — CHANGELOG + تقرير مرحلة + تحديث STATE بعد كل دفعة.
8. **الجوّال دائماً** — كل DoD بصري يُتحقق منه على 375px.

## 4) نموذج التنفيذ متعدد الوكلاء (Ultra Execution Model) — **v1.1**

**بروتوكول بدء كل تشغيل (إلزامي، بالترتيب):**
1. `git status` — **إن كانت الشجرة غير نظيفة:** طابِق مع دفتر STATE (أكمل-تحقّق-commit، أو تراجَع إلى `backup/pre-M<n>`) **قبل** أي fetch.
2. `git fetch origin` ثم فحص **انحراف التاريخ**: قارن merge-base مع `origin/dev SHA` المسجَّل في STATE — **أي انحراف non-fast-forward (force-push/rebase) = توقّف صلب → بوابة مؤسس**. التقدّم الطبيعي يُدمج بسياسة §2.1 ويُسجَّل SHA الجديد.
3. اقرأ دفتر المرحلة في STATE ونفّذ **الدفعة** التالية.

**إيقاع الدفعات:** استكشاف قراءة-فقط → [بوابة مؤسس إن لزم] → **بيان ملكية ملفات مكتوب** لكل dispatch مع فحص صفر-تداخل قبل الإطلاق → تنفيذ متوازٍ → تحقّق مركزي (lint 0 + build + tests + لا `<<<<<<<` + smoke عند البوابات) → **commit الدفعة** `M<n>.<batch>: ...` → تحديث دفتر STATE.

**الملفات المفردة (Singletons) — لا يحرّرها إلا المنسّق أو وكيل واحد مسمّى لكل دفعة:** `src/index.css` · `tailwind.config.js` · `package.json`+lock · `index.html` · جدول المسارات في `App.tsx` · `STATE.md` · `.claude/commands/*` · إعدادات eslint/ts/vitest/playwright/ci (وهذه الأخيرة تخضع أيضاً لقاعدة §2.4).

**قواعد الوكلاء:** لا npm/git إطلاقاً · ملكية حصرية · `ui/**` لوكيل واحد دائماً · فشل وكيل = إعادة الدفعة الناقصة فقط.

## 4.1) اقتصاد التنفيذ *(أُضيف في v2.1 — إلزامي لما تبقّى)*

رُصد أن الاستهلاك تضخّم لأسباب بنيوية لا لصعوبة العمل: كل وكيل فرعي يبدأ **بصفر سياق** فيعيد قراءة الملفات من جديد (ورشة واحدة بلغت 446 ألف توكن)، وultracode كان يوزّع أسطولاً حتى للمهام المفردة. القواعد التالية ملزِمة:

1. **العمل المباشر هو الأصل.** ينفّذ المنسّق بنفسه ما لم تتحقق **كل** الشروط: عمل متوازٍ فعلاً · ملفات منفصلة تماماً · **≥4 ملفات لكل وكيل**. المهمة المفردة أو التوثيقية أو الإعدادية → **لا وكلاء إطلاقاً**.
2. **سقف الوكلاء: 3 لكل مرحلة متبقية** (وليس لكل دفعة).
3. **البوابة الكاملة عند إغلاق المرحلة فقط** (build + كل الوحدات + E2E). داخل المرحلة: `eslint --quiet` + **الاختبارات المستهدَفة للملفات المتأثّرة** فقط.
4. **قراءة موجَّهة:** استخدم Grep/الأسطر المحدّدة بدل قراءة ملفات كاملة؛ لا تُعِد قراءة ما هو في السياق.
5. **لا إعادة توليد `coverage/` أو `dist/` إلا عند الحاجة الفعلية** (تقرير الإغلاق) — لا بعد كل دفعة.
6. **لا إعادة هيكلة واسعة النطاق جديدة** بعد هذه النقطة؛ ما تبقّى إتمام وتوثيق وتسليم لا إعادة بناء.

**ممنوعات المنفّذ (إضافة لممنوعات الأمر):** git المدمّر محلياً (`reset --hard` على غير ما وثّقته ROLLBACK، `branch -D backup/*`، `push --force`، `filter-branch`) · حذف فروع الأمان · تعديل بوابات المؤسس في STATE (تسجيل قراراتها فقط بعد ورودها من المؤسس نصاً).

|-----|---------|
