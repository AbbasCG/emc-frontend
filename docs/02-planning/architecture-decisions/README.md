# 🏛️ القرارات المعمارية (ADRs) — EMC Frontend

> **ADR = Architecture Decision Record:** توثيق مختصر لكل قرار تقني مهم، وسببه، وبدائله.
> يمنع تكرار النقاشات ويُبقي السبب وراء كل اختيار واضحاً للفريق الجديد.

## قرارات مقترحة تنتظر الحسم (من تقرير التقييم)
هذه قرارات يُنصح بحسمها وتوثيقها كـ ADR قبل التطوير الفعلي:
1. **توجيه الصفحات (Routing):** `react-router-dom` (مثبّت بالفعل) — تأكيد الاعتماد وبنية المسارات.
2. **إدارة الحالة (State):** Context API فقط؟ أم Zustand / Redux Toolkit / TanStack Query؟
3. **طبقة الـ API:** نمط استخدام `axios` (instance موحّد، interceptors، معالجة الأخطاء).
4. **التعريب (i18n):** مكتبة الترجمة ودعم العربية/الإنجليزية وRTL/LTR.
5. **منهج التنسيق:** Tailwind utility-first بالكامل؟ أم مزيج Tailwind + CSS وحدات؟ (حالياً Tailwind مثبّت لكن غير مُستخدم).
6. **الاختبارات:** Vitest + React Testing Library؟ + Playwright للـ E2E؟

## قالب ADR جديد
انسخ هذا القالب إلى ملف `ADR-NNNN-عنوان-مختصر.md`:

```markdown
# ADR-NNNN: <عنوان القرار>
- **الحالة:** مقترح | مقبول | مرفوض | متجاوَز بـ ADR-XXXX
- **التاريخ:** YYYY-MM-DD
- **القرار يخص:** <المجال>

## السياق
ما المشكلة/الحاجة التي تستدعي قراراً؟

## الخيارات المدروسة
1. الخيار أ — مزايا/عيوب
2. الخيار ب — مزايا/عيوب

## القرار
ما الذي اخترناه ولماذا.

## النتائج
الأثر المترتب (إيجابي وسلبي) والمخاطر.
```
